# 유선배 모의고사 1회와 SQLD Obsidian 연결망 대조 감사

- 원자료: [[2026. 7. 24. 20.00.pdf|유선배 기출변형 모의고사 1회 스캔]]

## 1. 감사 목적과 범위

- 개인 숙달도 분석이 아니다. 정답률·인출속도·취약도·합격 가능성은 이 보고서의 대상이 아니다.
- PDF(유선배 기출변형 모의고사 1회, 1과목 10문항 + 2과목 40문항 = 50문항, p.373~393)에 실제 등장한 개념·규칙·개념 간 관계와, 현재 `SQLD/Pilot`의 Concepts–Questions–Propositions 연결망을 대조하는 구조적·질적 감사다.
- 모의고사 한 회의 출제 결과를 SQLD 전체 출제분포로 일반화하지 않는다. 여기서 "누락"은 "이 1회 시험 기준으로 대응 근거가 부족하다"는 뜻이며, "SQLD 시험에서 절대 안 나온다/자주 나온다"는 뜻이 아니다.
- 이번 단계에서는 Concept·Question·Proposition·graph.json 어느 것도 수정하지 않는다. 실제 구조 수정 후보는 §14에만 기록한다.
- 1페이지(손필기 메모)는 사용자가 낯설게 느낀 용어 목록으로만 참고했고, 동그라미·체크·밑줄을 정답 여부나 숙달도 근거로 쓰지 않았다. 실제 출제 판정은 전부 2~22페이지의 문항·해설 원문을 근거로 했다.

## 5. 충분히 표현된 영역

A 판정 16개 규칙군은 대부분 SQL 파이프라인의 핵심 구간(WHERE/GROUP BY/HAVING/집계 함수/COUNT/NULL 비교/JOIN 행수/트랜잭션/DDL 분류/제약조건)이며, 이미 여러 세션에 걸쳐 다듬어진 영역과 일치한다. 특히 WHERE.md의 연산자 우선순위 규칙과 COUNT.md의 COUNT(상수) 규칙은 이번 PDF의 특정 문항(Q47, Q44)과 표현까지 거의 동일하게 맞아떨어져, 과거 보강 작업이 실제 기출 패턴을 정확히 겨냥했음을 보여준다. 정규화·데이터 모델링 3단계·주식별자 특징·ACID·TRUNCATE 등 이론 암기형 규칙군도 세부 조건까지 이미 문서화되어 있다.

## 6. Concept는 있으나 규칙이 부족한 영역

- **계층형 질의**: Concept는 있으나 START WITH·CONNECT BY PRIOR 기본 정의만 있다. PDF는 이 영역만으로 4개 문항(Q11, Q20, Q31, Q41)을 냈고, 그중 3개는 현재 문서화되지 않은 규칙(PRIOR 방향, 내장함수 목록, SELF JOIN 대체)을 요구했다.
- **윈도우 함수**: RANK 계열은 상세하나 RATIO_TO_REPORT(비율 함수, 순위 함수 아님)·FIRST_VALUE·RANGE 프레임은 없다.
- **집합 연산자**: UNION/UNION ALL/INTERSECT/MINUS는 있으나 EXCEPT(SQL Server 명칭)가 없다.
- **GROUP BY**: 실행 순서·SELECT 허용 항목은 있으나 "GROUP BY 절에서는 SELECT 별칭을 쓸 수 없다(Oracle)"는 규칙이 없다.
- **식별자**: 본질/인조 등 분류명은 나열돼 있으나 각 정의(업무적으로 생성 vs 원식별자가 복잡해 인위적으로 생성)는 없다.
- **ERD/식별 관계/비식별 관계**: Barker 표기(bar 기호)만 있고, PDF가 실제로 사용한 IE 표기(crow's-foot, 실선/점선)의 동일 규칙이 없다.

## 7. 개념 간 링크가 부족한 영역

- **연결이 필요한 Concept**: 계층형 질의 ↔ JOIN(SELF JOIN)
  - **PDF에서 함께 사용된 문항**: M01 대응 없음(PDF 자체 Q31, "계층형 쿼리를 JOIN 구문으로 작성할 때 적절한 JOIN"으로 SELF JOIN을 직접 지목)
  - **현재 링크 상태**: 계층형 질의.md의 "Related Concepts"가 "(없음 — 독립 문법)"으로 명시되어 JOIN·SELF JOIN 어느 쪽과도 링크 없음
  - **링크 보강 필요성**: 중간(계층형 질의 자체의 규칙 보강이 선행되어야 링크의 의미가 생김)

- **연결이 필요한 Concept**: 서브쿼리 ↔ JOIN
  - **PDF에서 함께 사용된 문항**: PDF Q39(인라인뷰 서브쿼리 결과를 JOIN·BETWEEN으로 다시 결합)
  - **현재 링크 상태**: 서브쿼리.md는 adjusted_content_degree=0인 완전 고립 노드(Related Concepts 섹션 자체가 없음)
  - **링크 보강 필요성**: 낮음(서브쿼리 자체 규칙 3개는 이미 core로 탄탄하며, 고립은 그래프 시각화 문제일 뿐 학습 우선순위와는 무관하다고 기존 보고서가 이미 판정함 — `실질-학습-우선순위.md` §5)

## 8. 부차적으로만 포함된 영역

- **반정규화**: 독립 Concept가 없고 정규화.md의 대조표 한 줄("정규화는 무결성 목적, 반정규화는 조회 성능 목적")로만 존재한다. PDF Q5는 반정규화 적용을 판단하는 4가지 구체 조건(입력 속도 저하 예상/집계 성능 저하 예상/JOIN 성능 저하 예상/함수적 종속 위반 없이 중복 허용)을 직접 시험 대상으로 삼았지만, 정규화 Concept 안에서는 검색해도 이 조건들을 찾을 수 없다.

## 11. NULL 중심성 대조

### 유선배에서 확인된 실제 역할
- 50문항 중 최소 10개 문항(Q12, Q17, Q18, Q22, Q32, Q33, Q34, Q37, Q40, Q44)에서 NULL이 정답 판별의 핵심 또는 필수 보조 조건으로 등장했다(데이터 모델링 10문항 제외, SQL 40문항 기준 25%).
- 결합된 방식: 비교 연산 불가(Q32, Q37), 집계 함수 제외 규칙(Q17, Q34, Q44), 집합 연산·WHERE 조합(Q18), IS NULL 판별(Q40), NULL 처리 함수(Q12, Q33).
- 정답 판별에 핵심이었던 경우: Q32(NOT IN+NULL), Q37(IN 목록의 NULL), Q34(행 연산 NULL 전파 vs 열 집계 NULL 제외) — 이 규칙을 모르면 선지를 좁힐 수 없다.
- 부차적 조건이었던 경우: Q18(NULL이 여러 조건 중 하나), Q40(GROUPING SETS 결과의 NULL이 소계 표시 용도로 등장 — 판별의 핵심은 GROUPING SETS 문법이지 NULL 자체가 아님).

### 현재 그래프와 일치하는 부분
- NULL이 WHERE·GROUP BY·집계·JOIN·정렬 5개 절 전부에서 규칙이 달라진다는 점은 이번 PDF에서도 그대로 재현되며, 이는 `실질-학습-우선순위.md`가 이미 1위로 판정한 근거(unique_rule_count=7, core_question_count=11, 둘 다 54개 중 최고)와 방향이 일치한다.
- NULL의 raw degree가 크다는 것 자체는 "여러 SQL 절을 관통하는 구조적 중심성이 실제로 크다"는 사실과 부합한다.

### 현재 그래프가 과장할 수 있는 부분
- axis_inflation(raw 14 중 4는 4개 축 메타링크)과 repetition_inflation(82%, SUM+NULL 규칙 반복)은 기존 보고서가 이미 수치화했다. 이번 PDF의 Q17·Q34·Q44도 "집계 함수와 NULL"이라는 이미 반복된 규칙을 재확인하는 성격이 강해, raw degree 14가 실제로 학습해야 할 서로 다른 규칙 7개보다 부풀려 보이게 만드는 구조는 이번 감사에서도 그대로 유지된다.

### 명시적 답변
- **NULL이 현재 가장 큰 노드인 것은 이번 모의고사 구조와도 대체로 일치하는가?** 대체로 일치한다. NULL이 관통하는 절의 수(비교/집계/집합연산/WHERE/GROUPING)가 이번 PDF에서도 그대로 재현됐다.
- **NULL의 노드 크기는 실제 출제관계 중 어느 부분을 잘 표현하는가?** "여러 절에 걸쳐 규칙이 달라진다"는 구조적 폭 자체는 잘 표현한다.
- **어느 부분은 단순 링크 부풀림인가?** 4개 축 메타링크(29%)와 SUM+NULL 규칙의 반복 출제(4문항)는 실제 학습량이 아니라 그래프 구조·문항 편성의 산물이다.
- **NULL보다 현재 그래프에서 저표현된 Concept는 무엇인가?** 계층형 질의(raw 0)·윈도우 함수(raw 1)·집합 연산자(raw 0)·서브쿼리(raw 2)는 raw degree가 NULL(14)의 1/7 이하지만, 이번 PDF에서 각각 최소 2문항 이상 독립 규칙으로 출제됐다.
- **NULL 중심 그래프가 SQLD 전체 연결망을 지나치게 단순화하고 있는가?** 단순화 위험은 "NULL이 크다 → NULL만 중요하다"로 읽을 때 발생한다. 이번 PDF는 계층형 질의·윈도우 함수·집합 연산자·LIKE ESCAPE처럼 raw degree가 작거나 0인 영역에서도 독립적인 판별 규칙을 요구했으므로, NULL 크기를 전체 우선순위의 대푯값으로 쓰면 이 영역들의 존재 자체가 가려진다.

**구조축에는 없지만 유선배에서 여러 문항을 연결하는 별도 관계축 후보**: 뚜렷한 5번째 축의 필요성은 확인되지 않았다. 대신 D축(Oracle과 SQL Server 차이)의 확정 범위가 이번 PDF 기준으로는 지나치게 좁다는 것이 가장 뚜렷한 신호다. `_reports/검토필요-분류.md`가 이미 D축 후보로 지목해 둔 집합 연산자·계층형 질의·문자형 함수·윈도우 함수 중, 집합 연산자(EXCEPT)와 계층형 질의(Oracle 전용 내장함수)는 이번 PDF에서 실제로 D축 근거가 나타난 것으로 보인다. 다만 이 판단은 이번 1회 모의고사만으로 내린 것이므로, 축 소속을 즉시 바꾸지 않고 §14 후보로만 남긴다.

**기존 구조축에 포함되지만 실제 문항관계가 드러나지 않는 Concept**: 집합 연산자·계층형 질의·윈도우 함수는 B축(SQL 작성 순서)에 소속돼 있지만 axis_membership만 부여됐을 뿐, PDF가 요구하는 세부 규칙(EXCEPT, 내장함수 목록, RATIO_TO_REPORT 등) 자체는 아직 본문에 없다.

## 16. 최종 결론

1. **현재 Vault는 유선배 모의고사 1회의 내용을 어느 정도 포괄하는가?** 규칙군 단위로 보면 A(충분) 16개, B(세부규칙 부족) 6개, C(관계 부족) 2개, D(부차적 포함) 1개, E(실질 누락) 3개로, 큰 틀에서는 절반 이상이 이미 충분히 표현되어 있고 나머지는 "완전히 새로운 영역"이 아니라 "이미 있는 Concept의 세부 규칙 보강"이 대부분이다.
2. **가장 큰 Concept 누락은 무엇인가?** LIKE(ESCAPE 포함)를 다루는 Concept가 전혀 없다. 58개 Concept 어디에도 대응 노드가 없다.
3. **가장 큰 규칙 누락은 무엇인가?** NULL 처리 함수(NVL/COALESCE/NULLIF/IFNULL)의 개별 동작·오류 조건. NULL 자체는 Vault에서 가장 두꺼운 Concept임에도, 정작 이 함수들의 이름과 차이는 어디에도 없다.
4. **가장 큰 관계 링크 누락은 무엇인가?** 계층형 질의 ↔ JOIN(SELF JOIN으로 대체 가능하다는 PDF Q31의 관계)이 전혀 링크돼 있지 않다.
5. **NULL 중심성이 유효했던 부분은 무엇인가?** WHERE·GROUP BY·집계·JOIN·정렬 5개 절에서 규칙이 모두 달라진다는 구조적 폭은 이번 PDF에서도 그대로 재현됐다.
6. **NULL 중심성이 과장된 부분은 무엇인가?** raw degree 14 중 4(29%)는 축 메타링크이고, SUM+NULL 규칙이 여러 문항(기존 4개 + 이번 PDF의 유사 패턴)에서 반복 확인되는 것이 링크 수를 부풀린다.
7. **가장 과소대표된 Concept는 무엇인가?** 집합 연산자와 계층형 질의(둘 다 raw degree 0). 그래프에서는 가장 작지만 이번 PDF에서 각각 5문항, 4문항과 관련됐다.
8. **현재 Concept 구조를 즉시 수정해야 하는가?** 아니다. 이번 감사는 진단이며, 수정은 §14의 후보 목록으로만 남긴다.
9. **추가 모의고사까지 기다려야 하는 수정은 무엇인가?** D축(Oracle과 SQL Server 차이) 소속 확장 여부. 집합 연산자·계층형 질의를 D축에 넣을 근거가 이번 PDF에서 나왔지만, 1회 시험만으로 축 소속을 바꾸면 과적합 위험이 있다.
10. **현재 연결망을 SQLD 출제구조 지도라고 볼 때 가장 큰 장점과 한계는 무엇인가?** 장점은 NULL·WHERE·집계 함수처럼 SQL 파이프라인 핵심부의 규칙이 이미 시험 수준으로 정교하다는 것이다. 한계는 계층형 질의·윈도우 함수·집합 연산자·LIKE처럼 "표면적으로 작아 보이는" 영역들이 실제로는 독립적인 판별 규칙을 요구하는데, 현재 그래프의 시각적 크기(raw degree)가 이 영역들의 실질적 중요도를 체계적으로 과소평가하고 있다는 점이다.
