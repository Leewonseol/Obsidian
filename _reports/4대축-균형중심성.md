# 4대축 균형 중심성 분석

## 0. 방법론

1. **Concept Graph**: Concept 파일 본문에 등장하는, 다른 Concept을 가리키는 명시적 위키링크만으로 구성한 무방향 그래프(54 노드, 95 엣지). Question·Proposition 링크는 제외.
2. **축별 중심성(`*_centrality`)**: 각 축에 소속된 Concept들만으로 유도 부분그래프(induced subgraph)를 만들고, 그 안에서의 degree centrality(연결수 / (해당 축 소속 개수-1))를 계산. 즉 "그 축 내부에서 다른 축 동료 개념과 얼마나 잘 연결되어 있는가"를 측정한다. 축에 속하지 않으면 해당 축 중심성은 0으로 처리.
3. **min_axis_centrality**: 4개 축 중심성(비소속 축은 0) 중 최솟값. 4축 모두에 속하지 않으면 자동으로 0이 되어 순위에서 밀려난다.
4. **geometric_mean_axis_centrality**: 4개 축 중심성의 기하평균(하나라도 0이면 전체가 0). 산술평균과 달리 "한 축만 매우 높고 나머지가 낮은" 개념이 상위에 오르는 것을 방지한다.
5. **concept_betweenness**: Concept Graph 전체(54 노드)에서 계산한 betweenness centrality.
6. **정렬 기준**(지시문 5항 그대로 적용): axis_coverage_count 내림차순 → min_axis_centrality 내림차순 → geometric_mean_axis_centrality 내림차순 → concept_betweenness 내림차순 → (evidence_question_count+evidence_proposition_count) 내림차순.

## 3. 해석

- **coverage=4는 NULL이 유일**하므로, 정렬 1순위(coverage desc)만으로 사실상 1위가 결정된다. 2~4위(ORDER BY/JOIN/DDL, 모두 coverage=3)는 min_axis_centrality가 전부 0.0000으로 동률인데, 이유는 단순하다 — 정의상 "속하지 않는 축의 중심성은 0"이므로, 3축에만 속한 개념은 나머지 1개 축이 그대로 min이 된다(JOIN은 D 미소속→D=0이 min, ORDER BY는 A 미소속→A=0이 min, DDL은 C 미소속→C=0이 min). 즉 coverage=3 개념들은 min_axis_centrality로는 서로 구분되지 않고, 4순위 기준인 betweenness에서 갈린다: ORDER BY(0.0457) > JOIN(0.0402) > DDL(0.0181) 순.
- **5위 이하(coverage=2)** 그룹은 대부분 B·C(SQL 작성순서·실행순서) 조합이며, 이는 SQL 절 단위 개념들이 "작성 위치"와 "실행 순서"라는 두 축에서 자연스럽게 동시에 강하다는 것을 보여준다. A·D 조합이나 A·B 조합(제약조건)은 상대적으로 드물다.
- **betweenness 상위권**(ERD 0.4091, PK 0.3636, 식별자 0.3636, FK 0.3636)은 axis_coverage=1(A축 전용)임에도 전체 그래프에서는 매우 중심적이다 — 이는 "축 내부 균형"과 "그래프 전체 다리 역할"이 서로 다른 지표임을 보여주는 사례다. 지시문이 요구한 "4개 축 균형"은 이런 A축 단독 허브들을 상위로 끌어올리지 않도록 설계되어 있으며, 실제로 이 개념들은 순위 19~22위에 머문다.

## 4. 근거(Question·Proposition) 충분성

NULL(Q16/P46), 집계 함수(Q8/P22), 윈도우 함수(Q3/P12) 등은 근거가 두터운 반면, 서브쿼리·집합 연산자·CROSS JOIN 등은 axis_coverage=2이면서도 근거 Question이 1~2개에 불과해 "균형은 있으나 근거는 얕은" 개념으로 구분된다. 최종 우선순위 5번째 기준(근거 충분성)은 coverage·min·geomean·betweenness가 모두 동률일 때만 작동하므로 이번 결과에서는 순위를 뒤바꾸지 않았다.
