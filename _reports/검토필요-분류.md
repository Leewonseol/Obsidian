# 검토 필요 분류 항목

16개 Concept이 `axis_review_required: true`로 표시됨. 근거 불충분 또는 복수 해석 가능 사유별로 분류.

## 1. D축(Oracle/SQL Server 차이) 후보이나 본문에 한쪽 DBMS만 언급됨

과제 지시문은 "SQLD 범위에서 명시적으로 다른 것만 차이점으로 분류"하라고 명시했다. 아래 항목들은 Oracle 또는 SQL Server 중 한쪽만 본문에 언급되어 있고, 반대쪽과의 명시적 대조 서술이 없어 D축을 확정하지 않았다.

| Concept | 본문에 있는 한쪽 서술 | 결여된 것 |
|---|---|---|
| DCL | "Oracle에서 REVOKE 시 하위 권한 연쇄 회수" | SQL Server의 대응 동작 서술 없음 |
| DROP | "Oracle의 DROP TABLE CASCADE CONSTRAINTS" | SQL Server 대응 구문 서술 없음 |
| COMMIT | "DDL 실행 시 Oracle에서는 자동으로 COMMIT" | 이는 AUTO COMMIT 노드의 내용을 참조하는 것으로, COMMIT 자체의 DBMS 차이는 아님 |
| ROLLBACK | "DDL 실행(Oracle 자동 COMMIT) 이후에는 되돌릴 수 없다" | 위와 동일하게 AUTO COMMIT 참조 성격 |
| Transaction | "Oracle의 DDL 실행은 자동으로 트랜잭션을 확정" | 위와 동일 |
| 계층형 질의 | "START WITH·CONNECT BY PRIOR...Oracle 질의 방식" | SQL Server의 재귀 CTE 등 대응 방식과의 대조 없음 |
| 문자형 함수 | "LENGTH/LEN: 문자열 길이" | 어느 DBMS가 LENGTH를, 어느 쪽이 LEN을 쓰는지 대조 서술 없이 병기만 되어 있음 |
| 윈도우 함수 | "TOP(n) WITH TIES(SQL Server)" | Oracle의 대응 구문(FETCH FIRST ... WITH TIES)과의 대조 없음 |
| 정규표현식 함수 | "REGEXP_COUNT: Oracle에서 지원되며" | SQL Server 미지원 여부가 명시적으로 대조되지 않음 |
| 자료형 | "Oracle 주요 자료형: VARCHAR2, NUMBER, DATE" | SQL Server 대응 자료형(VARCHAR, INT/DECIMAL, DATETIME 등)과의 명시적 대조 없음 — 지시문 예시 "자료형 및 형변환 차이"의 가장 유력한 후보이나 현재 본문으로는 확정 불가 |
| 집합 연산자 | "MINUS: ... 차집합" | EXCEPT·SQL Server 언급이 전혀 없음("Related Concepts: 없음"으로 명시됨). 지시문 예시 "MINUS/EXCEPT"의 가장 유력한 후보 |
| JOIN / OUTER JOIN | (해당 없음) | 지시문 예시 "Oracle 구식 OUTER JOIN(+)"에 대응하는 서술이 JOIN.md·OUTER JOIN.md 어디에도 없음 — 두 파일 모두 검토 필요 |
| PIVOT·UNPIVOT | "원본 마인드맵에는 PIVOT·UNPIVOT 자체에 대한 서술이 전혀 없다"(본문 자체 명시) | 콘텐츠 자체가 매우 얇음(low confidence). Oracle 11g+/SQL Server 간 실제 차이가 있으나 본문 미반영 |

**권고**: 2차 단계 이전에 위 항목들의 본문을 보강(SQL Server 또는 Oracle 쪽 대응 서술 추가)한 뒤 D축 재검토를 진행하는 것을 권장한다. 본문 보강 없이 axis_membership에 oracle_sqlserver를 추가하는 것은 "키워드만으로 억지 분류"에 해당할 위험이 있다.

## 2. 축 소속 자체가 모호한 개념

| Concept | 상태 | 사유 |
|---|---|---|
| ACID | axis_membership: [] (무소속) | TCL/Transaction의 "성질(이론)"을 설명하며, 표면 문법 위치(B)도 실행순서(C)도 모델링(A)도 DBMS차이(D)도 아님. TCL과 밀접하지만 "문법"이 아니라는 점에서 B축에도 강하게 넣기 어려움. axis_confidence: low |
| IN·NOT IN | B축만, confidence medium | 지시문의 축 B 목록에 "IN·NOT IN"이 별도 항목으로 명시되어 있지 않아 WHERE의 하위 요소로 간주함. 실행순서(C) 축 포함 여부도 불확실 |

## 3. 고아 Concept Node (Concept Graph degree 0)

Concept 본문에 다른 Concept으로 향하는 위키링크가 전혀 없고, 다른 어떤 Concept도 이 개념을 링크하지 않는 7개 노드:

- VIEW — 관련 개념 섹션 없음(기존 degree=1이었으나 실제로는 0으로 재계산됨 — stale 값 의심)
- 계층형 질의 — "관련 개념" 섹션 자체가 없음(원본에 없어 보강됨)
- 문자형 함수, 숫자형 함수, 정규표현식 함수 — 세 함수군 모두 서로 또는 다른 개념과 링크되어 있지 않음
- 서브쿼리 — 관련 개념 섹션 없음
- 집합 연산자 — "Related Concepts: (없음 — 독립 문법)"으로 명시

이 7개는 모두 "원본 마인드맵에는 없어 PDF 해설로 보강됨" 계열 개념으로, 원본 콘텐츠 자체가 얇아 다른 개념과의 연결이 아직 만들어지지 않은 상태다. 2차 단계에서 axis_membership을 추가하더라도 Concept Graph 상의 고립은 별개 문제이므로 함께 해결되지 않는다(허브 파일 링크 추가는 이 고립을 완화할 수 있음).

## 4. 지시문 예시와 실제 Concept Node 간 콘텐츠 공백

D축의 지시문 예시 중 아래 항목은 현재 어떤 Concept Node에도 대응하지 않는다(신규 개념 생성은 금지 사항 6항에 해당하므로 생성하지 않고 보고만 함):

- 문자열 연결 연산자(`||` / `+`) 자체의 별도 노드
- CHR / CHAR
- SYSDATE / GETDATE
- EXTRACT / DATEPART
- NVL / ISNULL
- DECODE (Oracle 전용 여부)

이들은 모의고사 원본에 아직 등장하지 않았거나, 등장했더라도 별도 Concept Node로 분리되지 않은 것으로 추정된다.
