# SQLD 실질 학습 우선순위

## 1. 지표 해석 방법

- **raw degree는 구조적 연결량이다.** 4대 축(데이터 모델링에서 JOIN까지·SQL 작성 순서·SQL 논리적 실행 순서·Oracle과 SQL Server 차이) 인바운드 링크 수와, 다른 atomic Concept와의 콘텐츠 링크 수를 단순히 합친 값이다. 이 값이 크다고 해서 "공부할 내용이 많다"는 뜻은 아니다.
- **adjusted_content_degree(축 제외 순수 콘텐츠 연결)도 가족 상호나열의 영향을 받을 수 있다.** 예를 들어 SQL 관리구문 계열(DDL·DML·TCL·DCL·COMMIT·ROLLBACK·Transaction 등)이나 ER 모델링 계열(PK·FK·식별자·관계·엔터티 등)은 서로를 본문에서 나열하는 방식으로 콘텐츠 링크를 주고받는다. 이 경우 axis_links는 0~1이어도 adjusted_content_degree만 높게 나올 수 있다(예: 관계=5, 속성=4, TCL=6 — 전부 Question·Proposition 근거가 0~1건뿐).
- **학습 우선순위는 unique_rule_count(실제로 서로 다른 판별규칙의 수)와 core_question_count(핵심 판별에 쓰인 Question 수)를 중심으로 본다.** 이 두 지표는 구조적 링크 수와 무관하게, Question·Proposition 본문을 직접 읽어 "이 규칙을 모르면 정답을 못 고르는가"를 기준으로 산정했다.
- **그래프에서 큰 노드가 반드시 공부할 내용이 많은 Concept는 아니다.** raw_degree 1~2위(NULL=14, DDL=13)와 raw_degree 최하위권(정규표현식 함수=1, 서브쿼리=2, 윈도우 함수=3)을 비교하면, 후자가 오히려 core_question_count·unique_rule_count 모두 견실하다(§5 참고).

**재계산 방법 요약**: `Concepts/*.md`(58개 중 축 노트 4개 제외 54개) · `Questions/*.md`(50개, 폴더로 판별) · `Propositions/*.md`(200개, 폴더로 판별)를 코드블록 제외 후 직접 파싱했다. Question·Proposition은 "핵심 판별 기준"·"이 선지가 시험하는 개념 관계"·"Judgment" 섹션을 전량 정독해 A(핵심)/B(보조)/C(부차)/D(템플릿중복)로 분류했으며, core_question_count·core_proposition_count는 A+B만 합산했다. 기존 `_reports`의 수치는 참조하지 않았다.

## 3. 최우선 학습 Concept (사전식 정렬 상위 10개)

### 1위 [[NULL]] (규칙 7 · 핵심Q 11 · 핵심P 38)
- **핵심 학습 규칙**: ① =/!=로 NULL 비교 불가, IS NULL만 가능 ② 집계함수(SUM/AVG/MAX/MIN)는 NULL 제외, COUNT(*)만 예외 ③ COUNT(*) vs COUNT(열) 차이 ④ OUTER JOIN 비매칭측은 NULL로 채움 ⑤ NOT IN 목록에 NULL 있으면 전체가 UNKNOWN ⑥ NVL/ISNULL/NULLIF/COALESCE의 동작 차이 ⑦ UNPIVOT EXCLUDE/INCLUDE NULLS 옵션
- **관련 핵심 Question**: [[M01-Q11]] [[M01-Q13]] [[M01-Q14]] [[M01-Q19]] [[M01-Q22]] [[M01-Q26]] [[M01-Q27]] [[M01-Q29]] [[M01-Q32]] [[M01-Q38]] [[M01-Q49]]
- **핵심 Proposition**: 위 11개 Question에 딸린 선지 중 38개(전체 연결 47개 중 부차 9개 제외)
- **다른 단원과 연결되는 방식**: SELECT·WHERE·JOIN·GROUP BY·ORDER BY 5개 절 전부에서 규칙이 달라지는 유일한 개념 — SQL 전체를 관통
- **raw degree와 실질 우선순위가 다른 이유**: raw=14 중 4는 4대 축 인바운드(구조적 메타링크)이며, 나머지 10 중에서도 집계함수 규칙이 여러 문항에 반복 등장한다. 그런데도 unique_rule_count=7은 54개 전체 1위이므로, 부풀림을 걷어내도 순위가 그대로 1위에 남는 유일한 사례다.
- **중복 출제 vs 별도 학습**: SUM(집계함수)의 NULL 제외 규칙이 [[M01-Q11]]·[[M01-Q29]]·[[M01-Q38]]·[[M01-Q49]] 4개 문항에서 각도만 바꿔 반복 확인된다(사실상 1개 규칙의 4차 검증). 반면 나머지 6개 규칙(비교연산·COUNT 구분·OUTER JOIN·NOT IN·NVL계열·UNPIVOT옵션)은 서로 완전히 독립적이라 각각 별도로 학습해야 한다.

### 2위 [[정규화]] (규칙 4 · 핵심Q 3 · 핵심P 13)
- **핵심 학습 규칙**: ① 1NF=도메인 원자성 유지 ② 2NF=부분 함수 종속 제거 ③ 3NF=이행 함수 종속 제거 ④ BCNF=모든 결정자가 후보키
- **관련 핵심 Question**: [[M01-Q03]] [[M01-Q06]] [[M01-Q08]](복합 식별자 실전 적용 포함)
- **핵심 Proposition**: 13개(연결 14개 중 [[M01-Q02-O4]]만 데이터 모델링 관점 문제 속 부차 언급으로 제외)
- **다른 단원과 연결되는 방식**: [[데이터 모델링 3단계]](논리적 모델링)와 [[함수적 종속]]을 잇는 A축 핵심 허브
- **raw degree와 실질 우선순위가 다른 이유**: raw_degree=4로 54개 중 31위권에 불과해 그래프에서는 눈에 띄지 않지만, 4개의 뚜렷이 구분되는 규칙과 3개 문항의 탄탄한 근거 덕에 실질 우선순위 2위 — "저평가가능" 태그의 대표 사례
- **중복 출제 vs 별도 학습**: 2NF(부분 종속 제거) 규칙이 [[M01-Q03]]·[[M01-Q06]]·[[M01-Q08]] 세 문항에 걸쳐 3~5회 반복 확인된다. 1NF/2NF/3NF/BCNF 4개는 서로 다른 규칙이므로 각각 별도 학습이 필요하다.

### 3위 [[TRUNCATE]] (규칙 4 · 핵심Q 2 · 핵심P 8)
- **핵심 학습 규칙**: ① WHERE 없이 전체 삭제만 가능 ② DDL이라 자동커밋되어 ROLLBACK 불가 ③ UNDO 로그를 안 남겨 DELETE보다 빠름 ④ 테이블 구조는 유지
- **관련 핵심 Question**: [[M01-Q46]] [[M01-Q47]]
- **핵심 Proposition**: 8개 전부
- **다른 단원과 연결되는 방식**: [[DELETE]]·[[DROP]]과의 3자 비교를 통해 DML·DDL 경계를 학습시키는 B축 핵심
- **raw degree와 실질 우선순위가 다른 이유**: raw=5로 중간 수준이지만 4개 독립 사실이 전부 근거탄탄하게 테스트되어 3위로 상승
- **중복 출제 vs 별도 학습**: 중복 없음 — 4개 규칙이 서로 다른 선지에서 독립적으로 확인된다.

### 4위 [[집계 함수]] (규칙 3 · 핵심Q 5 · 핵심P 20)
- **핵심 학습 규칙**: ① SUM/AVG/MAX/MIN은 NULL 제외 ② COUNT(*)는 포함, COUNT(열)은 제외 ③ AVG는 분모(행 수)에도 NULL 제외
- **관련 핵심 Question**: [[M01-Q11]] [[M01-Q20]] [[M01-Q29]] [[M01-Q38]] [[M01-Q49]] — core_question_count 5개는 54개 전체 최다
- **핵심 Proposition**: 20개(연결 23개 중 3개는 GROUP BY/WHERE 오류 원인 판별 등 부차)
- **다른 단원과 연결되는 방식**: GROUP BY 이전·이후 파이프라인 전체를 관통하며, [[NULL]]과 4개 문항([[M01-Q11]]·[[M01-Q29]]·[[M01-Q38]]·[[M01-Q49]])을 그대로 공유
- **raw degree와 실질 우선순위가 다른 이유**: axis_inflation 29%와 repetition_inflation 85%가 겹쳐 raw=7의 상당 부분이 부풀려져 있지만, core_question_count가 5로 최다라 4위를 유지한다.
- **중복 출제 vs 별도 학습**: NULL과 완전히 동일한 반복 패턴(SUM+NULL 규칙이 4문항에 반복)을 공유하는 "쌍둥이 부풀림" 사례다. [[NULL]]을 학습할 때 이 규칙은 함께 정리하고, COUNT(*) 구분·AVG 분모규칙만 추가로 학습하면 된다.

### 5위 [[윈도우 함수]] (규칙 3 · 핵심Q 3 · 핵심P 12)
- **핵심 학습 규칙**: ① DENSE_RANK는 동일값 동일순위 부여 + 다음 순위를 건너뛰지 않음 ② TOP WITH TIES는 동점 행까지 포함 ③ ROWS BETWEEN은 지정 범위만큼 물리적 이동 합계
- **관련 핵심 Question**: [[M01-Q23]] [[M01-Q24]] [[M01-Q35]]
- **핵심 Proposition**: 12개 전부
- **다른 단원과 연결되는 방식**: [[ORDER BY]] 정렬에 종속되는 함수군(콘텐츠 링크는 ORDER BY 1개뿐)

## 6. NULL 해석

| 항목 | 값 |
|---|---|
| 4개 축 소속 | A·B·C·D 전부(54개 중 유일) |
| raw degree | 14(전체 1위) |
| 축 제외 adjusted_content_degree | 10(DDL과 공동 1위) |
| 핵심 Question 수 | 11(전체 1위) |
| 핵심 Proposition 수 | 38 |
| 고유 규칙 수 | 7(전체 1위) |
| 반복 출제 비율(repetition_inflation) | 82% |
| axis_inflation | 29%(raw 14 중 4는 축 인바운드) |

**부풀림을 제거한 뒤에도 중요한 이유**: NULL의 raw_degree 14 중 4(29%)는 4대 축 메타링크이고, repetition_inflation 82%는 SUM+NULL 제외 규칙이 [[M01-Q11]]·[[M01-Q29]]·[[M01-Q38]]·[[M01-Q49]] 4개 문항에 반복 등장하기 때문이다. 이 두 부풀림 요인을 모두 걷어낸 뒤에도 **unique_rule_count=7과 core_question_count=11은 각각 54개 전체 1위**로 남는다. 즉 NULL이 큰 이유의 일부(축 4개, 반복 4문항)는 실제로 부풀림이 맞지만, 남은 부분(비교연산·COUNT구분·OUTER JOIN·NOT IN·NVL계열·UNPIVOT옵션 등 6개 독립 규칙)만으로도 이미 다른 어떤 Concept보다 학습 범위가 넓다.

**"NULL은 부풀려졌지만 여전히 실질 학습 우선순위가 높다"는 이전 판정은 이번 재계산에서도 그대로 유지된다** — raw_degree 순위 1위와 사전식 실질 순위 1위가 정확히 일치하며(§4/§5의 "5단계 이상 변동" 목록에 NULL이 등장하지 않는 이유), 이는 NULL이 "부풀려졌지만 순위가 유지된 유일한 최상위 개념"이라는 뜻이다. 반면 DDL(raw 2위→실질 16위)은 같은 방식으로 부풀려졌지만 실질 순위는 크게 하락한다 — 두 개념의 raw_degree가 비슷해도(14 vs 13) 부풀림을 걷어낸 후의 격차는 매우 크다.

## 7. 학습 적용 방법

1. **unique_rule_count가 높은 Concept부터 규칙을 분리해 암기한다.** §2 순위표의 1~11위(NULL·정규화·TRUNCATE·집계 함수·윈도우 함수·정규표현식 함수·ERD·서브쿼리·FK·DCL·함수적 종속, 고유 규칙 2개 이상)를 우선 순서로 삼되, 표에 나열된 "핵심 학습 규칙" 목록 단위로 쪼개서 암기한다 — Concept 하나가 아니라 규칙 하나가 암기 단위다.
2. **core_question_count가 높은 Concept는 문제를 반복 풀이한다.** NULL(11)·집계 함수(5)·GROUP BY·HAVING·COUNT·DCL·정규화·함수적 종속(각 3)은 실전 문제 노출 빈도가 높으므로 §3에 나열된 관련 핵심 Question을 실제로 다시 풀어본다.
3. **repetition_inflation이 높은 Concept는 동일 규칙의 반복 문제를 묶어서 학습한다.** HAVING(89%)·OUTER JOIN(88%)·WHERE(86%)·집계 함수(85%)·DCL(83%)·함수적 종속(82%)·NULL(82%)처럼 반복률이 80% 이상인 Concept는, 서로 다른 문항이라도 실제로는 규칙 1~2개의 재확인인 경우가 많다. 예를 들어 NULL·집계 함수의 "SUM은 NULL 제외" 규칙은 [[M01-Q11]]·[[M01-Q29]]·[[M01-Q38]]·[[M01-Q49]] 4문항을 한 세트로 묶어 한 번에 정리하고, DCL의 WITH GRANT OPTION 규칙은 [[M01-Q44]]·[[M01-Q45]]가 동일 시나리오임을 인지한 뒤 1회만 학습한다.
