## 3. 개념별 분류 근거 요약

### 4개 축 이상 걸치는 핵심 개념

**NULL** (A·B·C·D, confidence: medium)
- A: 본문에 "[[PK]] 컬럼은 NULL을 저장할 수 없다(존재성)" — 식별자/PK 규칙과 직결(medium)
- B: IS NULL/IS NOT NULL 비교 연산자 작성 규칙(medium)
- C: WHERE 필터·집계 제외·JOIN NULL 채움·정렬 등 여러 실행 단계별 처리 규칙이 본문에 명시(high)
- D: 본문에 "정렬(ORDER BY) 시 NULL의 위치는 Oracle과 SQL Server가 서로 다르다"가 명시적으로 서술됨(high)

### 3축 개념

**ORDER BY** (B·C·D, high) — B·C는 지시문 목록에 명시적으로 포함, D는 본문에 "NULL 정렬 순서는 Oracle과 SQL Server가 다르다" 명시.

**JOIN** (A·B·C, high, review_required) — A는 지시문 자체가 축 A의 마지막 단계로 명시("SQL 조회 단계에서 JOIN으로 관계 복원"), B·C는 목록에 명시적 포함. D는 제외했는데, "Oracle 구식 OUTER JOIN(+)" 차이가 JOIN.md·OUTER JOIN.md 어디에도 본문 서술이 없기 때문이다(검토필요-분류.md 참조).

**DDL** (A·B·D, medium) — A는 물리적 구현(테이블 생성)을 실행하는 명령어군이라는 논리로 medium, B는 목록에 명시적 포함, D는 본문이 [[AUTO COMMIT]](D 확정 노드)으로 직접 연결되어 있어 관련개념 링크 근거(우선순위 2번)로 medium 확정. C는 제외 — DDL 문은 SELECT의 논리적 실행 파이프라인 단계가 아니므로.

### 2축 개념(B·C 그룹, 대부분 high)

WHERE, GROUP BY, HAVING, ORDER BY(위 3축에 포함), JOIN(위 3축), 집계 함수, COUNT, OUTER JOIN, CROSS JOIN, 서브쿼리, 집합 연산자, 윈도우 함수, 그룹함수 확장 — 모두 지시문의 B축·C축 목록에 각각 명시적으로 이름이 나열되어 있어 high confidence로 양쪽 확정.

### 2축 개념(B·D 그룹)

ALTER, AUTO COMMIT — 본문에 Oracle/SQL Server 양쪽 문법이 명시적으로 대조되어 D축 high confidence. B축은 DDL/TCL 문법 범위에 포함되어 확정.

### A·B 동시 소속

**제약조건** (medium) — PK/FK/UNIQUE/CHECK 규칙을 총괄해 축 A(물리적 구현)의 핵심이면서, 동시에 "DDL로 선언"되는 문법 요소라는 점에서 B축과도 연결. D축은 제외 — CASCADE/SET NULL 등 옵션이 두 DBMS에서 본문상 명시적으로 대조되지 않음.

## 5. 구조적 관찰 — 지시문 예시와 실제 Concept Node 간 간극

축 D(Oracle과 SQL Server 차이)의 지시문 예시 중 다음 항목은 **현재 54개 Concept Node 어디에도 대응하는 노드가 없다**:
