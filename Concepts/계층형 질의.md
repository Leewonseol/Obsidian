# 계층형 질의

## 한 줄 정의

START WITH·CONNECT BY PRIOR를 이용해 자기참조 관계를 트리 구조로 전개하는 Oracle 질의 방식이다.

## 핵심 규칙

- START WITH: 계층 전개를 시작할 최상위 행(루트) 조건을 지정한다.
- CONNECT BY PRIOR 자식컬럼 = 부모컬럼: 상위 행을 기준으로 하위 행을 재귀적으로 연결한다.
- LEVEL: 루트를 1로 하는 계층 깊이를 반환한다.
- CONNECT_BY_ROOT: 현재 행 기준 최상위 루트 행의 값을 반환한다.
- CONNECT_BY_ISLEAF: 현재 행이 최하위(리프) 행이면 1, 아니면 0을 반환한다.
- CONNECT_BY_ISCYCLE: CONNECT BY NOCYCLE과 함께 사용되며, 현재 행이 자기 자신의 하위 어딘가에 다시 나타나는 순환을 만들면 1, 아니면 0을 반환한다.
- SYS_CONNECT_BY_PATH(컬럼, 구분자): 루트부터 현재 행까지의 경로를 구분자로 이어붙인 문자열로 반환한다.
- NOCYCLE: CONNECT BY 절에 붙여 데이터에 순환 참조가 있어도 오류 없이 질의가 끝나도록 한다(이때 CONNECT_BY_ISCYCLE로 순환 발생 행을 표시할 수 있다).
- 원본 마인드맵에는 계층형 질의 자체에 대한 서술이 없다.

## PRIOR 방향

같은 CONNECT BY PRIOR 조건이라도 PRIOR가 어느 표현식에 붙는지에 따라 부모·자식 행의 비교 방향이 달라진다.

- `CONNECT BY PRIOR 자식컬럼 = 부모컬럼`: 이전 단계(PRIOR)의 자식컬럼 값을 현재 행의 부모컬럼과 비교하며 계층을 따라 내려간다(정방향 전개, 루트→리프).
- `CONNECT BY 자식컬럼 = PRIOR 부모컬럼`: PRIOR가 부모컬럼에 붙어 비교 기준이 반대가 되며, 역방향(리프→루트)으로 전개된다.
- 단순히 "PRIOR가 붙으면 부모"라고 암기하지 말고, PRIOR가 붙은 표현식이 상위 단계(이전 행)의 값을 가리킨다는 원리로 방향을 판단해야 한다.

## SELF JOIN과의 관계

계층형 질의와 SELF JOIN을 동일한 것으로 보지 않는다.

- SELF JOIN: 동일 테이블을 자기 자신과 결합해 부모·자식 한 단계 관계만 명시적으로 조회한다.
- 계층형 질의(START WITH ... CONNECT BY): 관계를 여러 단계에 걸쳐 재귀적으로 반복 탐색해 임의 깊이의 트리를 한 번에 전개한다.
- 한 단계 부모·자식 조회는 [[JOIN]]의 SELF JOIN으로도 대체할 수 있지만, 임의 깊이의 계층 전체를 전개하려면 계층형 질의가 더 직접적이다.

## 능동 회상

### 1. 계층형 질의에서 최상위(루트) 행을 지정하는 절은 무엇인가?

> [!success]- 답 확인
> START WITH.

### 2. CONNECT BY PRIOR는 무엇을 수행하는가?

> [!success]- 답 확인
> 상위 행을 기준으로 하위 행을 재귀적으로 연결한다.

### 3. `CONNECT BY PRIOR 자식컬럼 = 부모컬럼`과 `CONNECT BY 자식컬럼 = PRIOR 부모컬럼`의 전개 방향은 어떻게 다른가?

> [!success]- 답 확인
> 앞은 정방향(루트→리프), 뒤는 PRIOR가 부모컬럼에 붙어 역방향(리프→루트)으로 전개된다.

### 4. 현재 행이 리프인지 여부를 반환하는 함수는 무엇인가?

> [!success]- 답 확인
> CONNECT_BY_ISLEAF(리프면 1, 아니면 0).

### 5. 계층형 질의와 SELF JOIN은 항상 서로 대체 가능한가?

> [!success]- 답 확인
> 아니다. SELF JOIN은 한 단계 부모·자식 관계만 표현할 수 있고, 임의 깊이의 계층 전체를 전개하려면 계층형 질의가 필요하다.
