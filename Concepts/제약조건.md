# 제약조건

## 한 줄 정의

테이블에 저장될 데이터가 지켜야 하는 규칙을 DDL로 선언한 것이다.

## 핵심 규칙

- PRIMARY KEY: 중복 불가, NULL 불가, 테이블당 하나(복합키 가능) → [[PK]]
- UNIQUE: 중복 불가, NULL 허용, 테이블당 여러 개 가능
- NOT NULL: NULL 입력 금지
- CHECK: 지정한 조건·범위의 값만 허용
- FOREIGN KEY: 참조 무결성 보장(CASCADE / SET NULL / SET DEFAULT / NO ACTION·RESTRICT) → [[FK]]

## 판단 순서

1. 어떤 제약조건이 언급되었는지(PK/UNIQUE/NOT NULL/CHECK/FK) 식별한다.
2. 그 제약조건이 유일성 관련인지, NULL 관련인지, 값 범위 관련인지 구분한다.
3. [[개체 무결성]](PK 대상)인지 [[참조 무결성]](FK 대상)인지 구분한다.

## 자주 혼동하는 개념

| 비교 대상 | 차이 |
|---|---|
| PK vs UNIQUE | 둘 다 중복 방지, NULL 허용 여부만 다름 |
| CHECK vs NOT NULL | CHECK는 값의 조건·범위 제한, NOT NULL은 값의 존재만 강제 |

## 대표 함정

- CHECK나 UNIQUE 제약조건 설정을 PK 규칙(개체 무결성)과 혼동해 위반 여부를 잘못 판단(M01-Q01).

## 능동 회상 질문

1. 제약조건 5종은 무엇인가?
2. PK와 UNIQUE의 NULL 허용 여부 차이는?
3. CHECK 제약조건은 무엇을 제한하는가?

## 답 확인

1. PRIMARY KEY, UNIQUE, NOT NULL, CHECK, FOREIGN KEY.
2. PK는 NULL 불가, UNIQUE는 NULL 허용.
3. 지정한 조건·범위 내의 값만 허용한다.

## 관련 개념

- [[PK]]는 각 행을 유일하게 식별하며 UNIQUE와 NOT NULL 성격을 함께 요구한다.
- [[FK]]는 제약조건 중 유일하게 다른 테이블을 참조 대상으로 삼는다.
- [[개체 무결성]]은 제약조건 중 PK에 한정된 규칙이다.
