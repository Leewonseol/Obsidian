# 정규화

## 한 줄 정의

데이터 이상 현상을 방지하기 위해 함수적 종속 관계를 근거로 엔터티(테이블)를 분리하는 과정이다.

## 핵심 규칙

- 목적: 삽입 이상·갱신 이상·삭제 이상을 방지한다.
- 단계: 1NF → 2NF → 3NF → BCNF → 4NF → 5NF, 실무에서는 보통 3NF까지 적용한다.
- 1NF는 도메인 원자성을 "유지"하는 것이 목적이다(다중값을 원자적으로 분해).
- 2NF는 부분 함수 종속을 제거한다(복합 식별자의 일부가 다른 속성을 결정하는 경우 분리).
- 3NF는 이행 함수 종속을 제거한다.
- BCNF는 모든 결정자가 후보키가 되도록 만든다.
- 테이블을 분해할 때는 원래 테이블과의 연결을 위해 공통 키를 양쪽에 남겨야 한다.

## 판단 순서

1. 식별자(주식별자)를 확인한다.
2. 식별자와 나머지 속성 사이의 함수적 종속 관계(X→Y)를 나열한다.
3. 식별자 "전체"가 아니라 "일부"가 다른 속성을 결정하는지 확인한다(부분 함수 종속 → 2NF 대상).
4. 식별자가 아닌 일반 속성이 다른 일반 속성을 결정하는지 확인한다(이행 함수 종속 → 3NF 대상).
5. 분해 후 원래 테이블과 연결할 공통 키를 양쪽에 남긴다.

## 자주 혼동하는 개념

| 비교 대상 | 차이 |
|---|---|
| 1NF vs 2NF | 1NF는 원자성 유지, 2NF는 부분 함수 종속 제거 |
| 2NF vs 3NF | 2NF는 식별자 일부에 의한 종속 제거, 3NF는 일반 속성 간 종속(이행 종속) 제거 |
| 정규화 vs 반정규화 | 정규화는 무결성·품질 목적, 반정규화는 조회 성능 목적(트레이드오프) |
| 정규화 관점 | 존재하지 않는 개념 — "데이터/프로세스/상관" 3관점과 혼동하지 말 것 |

## 대표 함정

- "정규화 관점"이라는 존재하지 않는 관점을 실제 있는 것처럼 제시(M01-Q04).
- 1NF의 목적을 "원자성 유지"가 아니라 "원자성 제거"로 반대로 서술(M01-Q06).
- 부분 함수 종속을 찾아 분해할 때 원래 테이블에 연결 키(B)를 남기지 않고 완전히 쪼개버림(M01-Q08).
- 개념적 모델링 단계의 특징으로 "정규화 수행"을 잘못 배치(M01-Q02).

## 능동 회상

### 1. 부분 함수 종속을 제거하면 어떤 정규형이 되는가?

> [!success]- 답 확인
> 2NF.

### 2. 1NF의 목적은 원자성을 "제거"하는 것인가, "유지"하는 것인가?

> [!success]- 답 확인
> 유지하는 것이다.

### 3. 복합 식별자 {A,B} 중 B가 D를 결정할 때({B}→{D}), 이는 어떤 종속 유형인가?

> [!success]- 답 확인
> 부분 함수 종속이다.

### 4. 테이블을 분해한 뒤 원래 테이블과의 연결을 위해 무엇을 남겨야 하는가?

> [!success]- 답 확인
> 분해에 사용된 공통 키(예: B)를 양쪽 테이블에 남겨야 한다.

### 5. 정규화의 궁극적 목적은 무엇인가?

> [!success]- 답 확인
> 삽입·갱신·삭제 이상 현상을 방지하는 것이다.
